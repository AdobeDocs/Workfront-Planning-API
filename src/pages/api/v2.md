## Field creation

For `POST /v2/record-types/{recordTypeId}/fields`, omit the top-level `id` and
`imsOrgId`: these properties are server-managed. When copying a field response
into a create request, remove its top-level identity properties and choose a
unique `displayName` within the destination record type. Do not remove IDs that
identify linked fields.

The field-identity fix is being rolled out: where enabled, supplied top-level
identity properties are ignored and a new field ID is generated. This does not
make POST idempotent; repeating a create request is not an update to an existing
field.
